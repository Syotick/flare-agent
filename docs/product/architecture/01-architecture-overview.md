## 2. 组件职责与关键设计

### 2.1 Agent Runtime（核心，无状态）
- 只负责编排与调度，**不持有状态**；会话/任务状态定期 checkpoint 到 Redis/PG。
- 通过**事件总线**解耦长任务（沙箱执行、文档入库、批量任务）与同步热路径。
- 水平扩展：HPA 按 CPU/队列深度/在途请求扩缩；多可用区部署。

### 2.2 会话与记忆服务
- 短期（会话内，Redis，TTL）+ 中期（项目级，PG，如项目记忆/决策记录）+ 长期（可选向量记忆）。
- 上下文工程在运行时执行（截断/摘要/抽取），不污染原始记录。

### 2.3 工具 / MCP / Skills
- Tool Registry：内置工具 + MCP 客户端适配器 + Skills 解析。
- **MCP 网关**统一收敛第三方 server：认证/授权/限流/审计/白名单。
- 敏感工具权限分级，需要时触发人工审批（interrupt）。

### 2.4 RAG
- 入库管线（异步工作线程）：OSS 源 → 解析 → 分块 → 嵌入 → 向量库（版本化）。
- 在线检索：混合检索 + Rerank + 溯源；检索权限与租户对齐。
- 评测：RAGAS 离线 + 在线命中/反馈。

### 2.5 模型网关
- 单一 OpenAI 兼容入口；多供应商路由、灰度、降级、语义缓存、配额、成本。
- 自托管推理（vLLM/SGLang）以同样协议接入，可在网关后并行。

### 2.6 沙箱执行
- 每次执行独立容器/微虚机，网络出口白名单，资源限额，超时杀灭。
- 产物上传 OSS，执行记录入审计。

### 2.7 多租户治理（横切）
- 租户 ID 贯穿所有数据路径；行级权限 + 服务层强制过滤。
- 租户级配额（并发/token/成本）→ 网关限流 + 运行时预算。

## 3. 关键数据流

1. **任务流**：客户端 → 网关(限流/认证) → Runtime 建任务(写 PG/发事件) → 编排循环 → 调模型网关/工具/检索 → checkpoint → 结果入库 → 流式推送客户端。
2. **长任务流**：Runtime 将重活发到事件总线 → 工作线程消费（沙箱/RAG 管道）→ 结果事件回写 → 客户端收到进度。
3. **审批流**：编排遇敏感动作 → interrupt（状态持久化）→ 客户端审批 → 恢复执行。

## 4. 扩展策略（百万级并发路径）

| 层 | 扩展方式 |
| --- | --- |
| 接入 | 网关水平扩展 + 全局限流 |
| Runtime | 无状态 HPA；会话状态外置 |
| 工作线程 | 按队列深度独立扩缩（与热路径隔离） |
| 模型 | 多供应商分摊 + 自托管 GPU 集群（vLLM 连续批处理） |
| 存储 | RDS 读写分离 + Redis 集群 + 向量库分片 |
| 队列 | RocketMQ 分区扩容 |

## 5. 高可用设计

- 多可用区部署，PodDisruptionBudget，跨 AZ 数据主备。
- 幂等任务 + outbox 事件；重试/指数退避/熔断/降级。
- 定期灾备演练 + Chaos Mesh 注入故障。

## 6. 部署拓扑（阿里云）

- ACK 托管 K8s（多 AZ node pool：CPU 池 + GPU 池）
- MSE 网关 / SLB + ALB
- 云 RDS(PostgreSQL)、云 Redis、RocketMQ、OSS、ACR 镜像仓
- 向量库：自建 Milvus（K8s）或托管 DashVector
- 观测：Prometheus/Grafana（可托管 ARMS）+ SLS 日志 + OpenTelemetry Collector

## 7. 演进路线

1. **M2 MVP**：单租户、单模型、Web/CLI 端到端跑通（无沙箱先本地进程隔离演示）。
2. **M3**：RAG + 分层记忆 + 评测。
3. **M4**：模型网关多供应商 + 沙箱隔离 + 配额成本。
4. **M5**：多租户治理 + 云原生部署 + 压测 → 上线。
5. **M6**：私有化交付、技能市场、成本优化、SLO 运营。
