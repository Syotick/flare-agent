# 00 · 认识 Flare Agent

> 目标读者：会 Python / Node、知道 LLM 是什么，但第一次接触这个项目的人。
> 读完本篇你会明白：**Flare Agent 是什么、能帮你做什么、和 Claude Code / DeepSeek Harness 有什么区别**。

---

## 一句话

Flare Agent 是一个**自托管的 AI Agent 平台**：你给它一个目录当工作区，它能在这个目录里**读代码、写代码、搜索、跑命令**，分步完成你的任务；过程在 Web 控制台里实时可见，每一步工具调用都可控、可审批。

它长得像一个"AI 同事"：你打字下任务，它在旁边思考、翻代码、写文件、跑命令、给你看结果——而且它跑在**你自己的服务器**上。

## 它能做什么（都是真实现）

| 场景 | 你做什么 | Agent 做什么 |
| --- | --- | --- |
| 代码理解 | "总结一下这个项目的架构" | 用 `read` 读关键文件、`glob/grep` 搜代码，汇总成 Markdown 回复 |
| 写代码 | "写个 hello.py 并运行" | `write` 创建文件 → `bash` 运行 → 把输出回给你 |
| 修 bug | "这个报错怎么修" | 读报错 → 定位文件 → 改代码 → 重跑验证 |
| 查资料 | 问答 / 检索 | 从你导入的知识库（RAG）或记忆里找答案 |
| 多步任务 | "调研 X，整理成报告" | 一步步拆解，工具轨迹全程展示 |

## 它不做什么

- 不是模型训练 / 微调平台
- 不是无代码工作流（它是给**开发者**的，需要会命令行）
- 不做手机 App / 云端托管（当前版本本地优先）

## 和主流 Agent 工具对比

| | Claude Code | DeepSeek Harness (DSH) | **Flare Agent** |
| --- | --- | --- | --- |
| 形态 | 终端 CLI | 本地 IDE / Harness | **自托管 Web 控制台** |
| 谁能用 | 本机用户 | 本机用户 | 服务器上**多人 / 多会话** |
| 代码能力 | 读/写/跑（本机） | 读/写/跑（本机目录） | 工作区六工具（`read/write/edit/glob/grep/bash`） |
| 审批 | 有权限提示 | 有 | **审批门 + TOFU + 三种权限模式** |
| 扩展 | 插件 | 插件 | **MCP + Skills + 多 Agent + OpenAI 兼容 API** |
| 部署 | 本机 | 本机 | 你自己的服务器，随时可改代码 |

一句话：**Claude Code / DSH 是"个人助手"，Flare Agent 是"可二次开发的 Agent 平台"**——交互形态向它们看齐，但数据和能力都在你手里。

## 核心心智模型（记住这三个词）

```
任务 (Task)  —— 你说一句话，就是一个任务
工具 (Tool)  —— Agent 干活的手：读文件、写文件、跑命令…
审批 (Approval) —— 危险操作（写/跑命令）默认要你点头
```

几乎所有功能都是围绕这个三角展开的：
- **工作区**决定了 Agent 能用工具碰哪些目录
- **权限模式**决定要不要审批、能不能写
- **模型**决定了 Agent 的"脑子"是谁

## 技术栈一句话

- 后端：**FastAPI**（HTTP/SSE）+ **LangGraph**（Agent 编排，图式状态机 + 断点续跑）
- 前端：**React 18 + Vite + Tailwind v4 + shadcn/Radix**（对话界面 + 各控制台页）
- 存储：**SQLite**（任务 / 知识库 / 记忆，重启不丢；Redis 可切换）
- 模型：**多供应商网关**（mock / OpenAI 兼容 / Claude 原生）
